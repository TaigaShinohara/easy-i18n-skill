# ICU チートシート

## 基本の考え方

- ICU MessageFormat は文法を翻訳の中に置く仕組みである。コードは数や性別を渡すだけで、言語ごとの形の選び方は翻訳側が決める。

- プレースホルダは名前付きにする。位置だけの指定より翻訳者が意味を掴みやすく、順序の入れ替えにも強い。

- `other` は常に必須である。言語によって必要なカテゴリが違うため、翻訳者は自分の言語に要るカテゴリだけを足す。

## 複数形

- 書き方の例は `{count, plural, =0 {カートは空です} one {# 点} other {# 点}}` である。`=0` のような完全一致を先に置き、次にカテゴリを置く。

- カテゴリは `zero` と `one` と `two` と `few` と `many` と `other` の6種である。Unicode CLDR が言語ごとにどの数がどのカテゴリかを決めている。

- 言語ごとの形の数は大きく違う。日本語と韓国語と中国語は1種、英語とドイツ語は2種、ロシア語とポーランド語は4種、アラビア語は6種である。だから英語の2分岐をコードに書くと他の言語で必ず壊れる。

- Android のリソースファイルは ICU を直接書けない。代わりに `<plurals>` の `quantity` 属性で同じカテゴリを表す。中央カタログから変換する場合はこの対応が正しく出るかを最初に1件で試す。

## 選択と順序数

- 性別や状態で文が変わる場合は `{gender, select, female {彼女が} male {彼が} other {その人が}}` のように `select` を使う。

- 1番目や2番目などの順序は `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` のように `selectordinal` を使う。言語ごとに規則が違うため手書きしない。

## 数値と日付

- 文の中の数値は `{value, number}`、割合は `{value, number, percent}`、通貨は通貨コードと合わせて整形する。単独の表示では Web の `Intl.NumberFormat` と `Intl.DateTimeFormat` を使う方が簡単で確実である。

- 日付パターンを文字列で固定しない。`dd/MM/yyyy` のような書き方は国ごとに意味が変わる。ロケールに整形を任せる。

## 書くときの注意

- 文は完結した1文を1キーにする。主語だけ、動詞だけのような断片をキーにしない。

- プレースホルダの前後に言語依存の空白や助詞を固定しない。必要な空白は翻訳の中に含める。

- ネストは浅く保つ。複数形の中に選択を入れ子にするような文は、まず文自体を2つに分けられないか考える。
