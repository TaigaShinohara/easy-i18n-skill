# 落とし穴と確認リスト

## 落とし穴

- ハードコードの残りが最も多い事故である。エラー文、空状態、ツールチップ、アクセシビリティラベル、通知文は漏れやすいので最後に全文検索で確認する。

- 文字列の連結は語順と格と性別を壊す。必ず1つの完全なメッセージにする。

- 複数形をコードで分岐すると英語以外の言語で壊れる。ICU かプラットフォームの複数形リソースに寄せる。

- 日付と金額の手整形は国ごとの表記を壊す。ロケール整形に任せ、並び順も照合用の Collator を使う。大文字小文字の変換も言語依存であり、トルコ語などで事故になるため安易に使わない。

- 文字の膨張を見込まないとレイアウトが崩れる。目安としてドイツ語は約3割増し、フランス語は約2割増し、スペイン語とアラビア語は約25パーセント増し、中国語と日本語と韓国語は短くなるが字形が大きく行間も要る。幅固定のボタンと1行前提のラベルを作らない。

- RTL は単なる右寄せではない。論理プロパティを使い、戻る矢印や進行方向は反転し、時計や再生ボタンやロゴや電話番号は反転しない。双方向テキストの混在も実ロケールで確認する。

- フォントは言語ごとに確認する。Web で CJK フォントを全員に配らない。システムフォントの積み重ねや unicode-range による分割を使う。

- ロケールの選び方を雑にしない。スペイン語でも地域で語彙が違い、ポルトガル語のブラジルとポルトガルも違う。BCP 47 のタグを意図して選ぶ。

- 翻訳された文字列の値で分岐しない。分岐はキーやロケールコードで行う。

## 確認リスト

- 機械検証が通っている。キー集合とプレースホルダ集合が全ロケールで一致し、空訳がない。

- 擬似ロケールを1周した。ハードコードが英語のまま残らず、切れと重なりがない。

- 最も長い言語で主要画面を見た。ボタンと見出しとタブが切れていない。

- RTL を対応と名乗る場合は実 RTL ロケールで1周した。擬似 RTL だけで済ませていない。

- 複数形を 0 と 1 と 2 と 5 と 21 と 100 で表示した。全ロケールで文法が破綻していない。

- 日付と金額と割合を各ロケールで表示した。表記がその国の形になっている。

- 言語切り替えが保持され、OS やアプリ別言語設定に従う。

- キーを1つわざと消して表示した。生キーではなく既定言語に落ちる。

- ストア掲載文の翻訳がアプリ内翻訳とは別に済んでいる。タイトルと短い説明とスクリーンショットが先に揃っている。
