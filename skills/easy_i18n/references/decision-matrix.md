# 方式の判断表

調査日は 2026-11-16 である。ライブラリの版と価格は変わるため、採用前に公式ページで現行版を確認する。

## 正本の置き方

- 同じ製品が2つ以上のプラットフォームに出る場合は中央カタログ方式にする。正本は `messages/en.json`、他言語は `messages/<locale>.json` とし、プラットフォーム向けファイルは生成物として扱う。

- プラットフォームが1つだけの場合は中央カタログを作らない。そのプラットフォームの標準ファイルを正本にする。変換層が増えるほど壊れる場所が増えるためである。

- 中央とプラットフォーム側の両方を手で直す運用は禁止する。必ずどちらか一方だけを正本にする。

- 形式は JSON を既定にする。ほぼ全てのランタイムと翻訳道具がそのまま読めるためである。YAML は人が書く設定には向くが交換形式としては劣る。

## Web ライブラリの選び方

- Next.js の App Router の場合は next-intl を選ぶ。ICU が内蔵され、サーバーコンポーネントでそのまま使え、型の補完が標準で効く。Next.js 専用である点だけが制約である。

- Vite と React の新規プロジェクトでは Paraglide JS を選ぶ。コンパイラが型安全なメッセージ関数を生成し、使った文だけがバンドルに入る。提供元や Provider が不要で配線が小さい。コミュニティは他の候補より小さい。

- React Native や Electron とコードを共有する場合、または情報量とプラグインの多さを優先する場合は react-i18next を選ぶ。ICU はプラグインで足す。型安全は追加設定が要る。

- 人間の翻訳者と PO ファイルで回す場合は Lingui を選ぶ。抽出と厳格コンパイルが標準で、未訳をビルドで止められる。

- FormatJS の react-intl は ICU の厳密さが最優先の場合だけ選ぶ。実行時が大きく学習コストも高いため個人開発の既定にはしない。

- 新規では避けるものとして、App Router 向けの旧来の next-i18next、更新が止まっている typesafe-i18n、非推奨になった i18next-parser がある。i18next-parser の後継は i18next-cli である。

## Android の選び方

- Android 単体では標準リソースを選ぶ。`res/values/strings.xml` と言語別フォルダを使い、Compose では `stringResource()` と `pluralStringResource()` で読む。

- Kotlin Multiplatform で UI まで共有する場合だけ Compose Multiplatform のリソースを選ぶ。置き場所が `commonMain/composeResources` に変わるだけで考え方は同じである。

- 実行時の言語切り替えを標準より強くしたい場合やサーバー配信の文字列が要る場合だけサードパーティ製を検討する。その場合は Android Studio の翻訳エディタと Lint との互換を失う点を明記する。

## Chrome 拡張の選び方

- `chrome.i18n` を必ず使う。マニフェストの名前と説明とコマンドはこれでしか翻訳できない。ファイルは `_locales/<locale>/messages.json` で、キーごとにフォールバックが効くため部分訳でも安全である。

- Firefox 対応では webextension-polyfill 経由の `browser.i18n` を使う。ファイル形式と API は同じなのでカタログは1つで足りる。

- ポップアップ内の複雑な文だけに Web 用ライブラリを併用してよい。ただしマニフェスト側の代替にはならない。`chrome.i18n` には複数形がないため、複数形は `Intl.PluralRules` でキーを選ぶか ICU 整形を埋め込む。

## 翻訳道具の選び方

- 既定は Git と CLI だけにする。道具代はゼロである。

- LLM の CLI で差分だけ翻訳する方式が個人開発の既定である。ロックファイルで変わった文字列だけを処理する道具を使うと再翻訳が安く速くなる。

- 画面上で文脈を見ながら直したい場合は Tolgee の無料枠を検討する。実行中のアプリで文字列を直接選んで直せる点が強い。

- 2人目の人間の翻訳者が加わったら Crowdin の無料枠を検討する。個人で使うには設定の手間が翻訳作業自体を上回ることがある。

- Lokalise は個人開発の既定にしない。無料プランがなく料金がチーム向けである。
